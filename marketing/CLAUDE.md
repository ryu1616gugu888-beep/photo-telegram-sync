# CLAUDE.md (marketing/ 専用: 収益化・広告・SNS運用・note執筆)

このディレクトリは「iPhone写真→Telegram自動転送アプリ」の収益化に向けた集客・広告・執筆活動を担当する。
ルートの [../CLAUDE.md](../CLAUDE.md) の行動範囲の制約(アカウント新規作成・投稿の都度確認)を必ず守ること。

## このディレクトリの役割

アプリ本体(`dev/`)の価値が固まり次第、以下の活動を通じて認知拡大・収益化を進める:

1. **広告運用**: アプリ内広告(AdMob等)またはApp内課金/サブスクリプションの設計・訴求文言の検討
2. **SNSアカウント運用による短編動画生成**: TikTok/YouTube Shorts/Instagram Reels向けの台本・
   構成案・キャプション作成
3. **note記事執筆**: 開発の裏側、Google Photos一括移行の知見、プライバシー重視の設計思想などを
   コンテンツ化した記事のドラフト作成
4. **その他プラットフォームへの宣伝**: X(Twitter)/Threads/Product Hunt/Reddit等での告知文面作成

## 素材の置き場所

```
marketing/
├── CLAUDE.md
├── videos/       ← 短編動画の台本・構成案(Markdown)。実際の動画ファイルはここに置かない
├── articles/      ← note記事等のドラフト(Markdown)
└── posts/         ← X/Threads等の短文投稿ドラフト
```
(まだ存在しないディレクトリは、実際にコンテンツを作る際に作成してよい)

## コンテンツ制作の方針

- **ターゲット**: 「Google Photosの容量制限や広告に疲れた人」「写真を自動でバックアップ/整理したい人」
  「Telegramを既にヘビーに使っている人」を軸に、実体験(過去に2万枚以上を一括移行した経験)を
  一次情報として使えるのが強み。誇張や事実と異なる実績の記載はしない。
- **アプリの設計思想(オンデバイス処理・認証情報を開発者が預からない)は差別化ポイントとして
  積極的に打ち出す。** プライバシー訴求はnote記事・SNS両方の軸にしてよい。
- 短編動画の台本は「フック(3秒以内)→ 問題提起 → 解決策(アプリのデモ) → CTA」の型を基本とする。
- note記事は誇大な収益化煽り表現を避け、実装や設計判断の具体性(このプロジェクトの技術的知見)を
  読者価値として前面に出す。
- 生成した台本・記事・投稿文は必ずこのディレクトリにドラフトとして保存してからユーザーに提示する。

## Claude Codeの行動範囲(必ず遵守)

- **SNSアカウント・note ID等の新規作成はClaude自身が行わない。** ユーザー本人に作成してもらい、
  必要であればログイン後の操作手順を案内する。
- **台本・記事・キャプションの下書き作成は自由に行ってよい。** ただし以下は毎回ユーザーの明示的な
  許可を取ってから実行する(ルートCLAUDE.mdの安全ルールと同一):
  - note/X/Threads等への実際の**投稿・公開**
  - 広告出稿の設定(予算確定・支払い情報の入力を伴う操作)
  - フォーム送信、規約同意、OAuth連携の許可
  - 動画のレンダリング後のアップロード操作(TikTok/YouTube等へのアップロード自体)
- ブラウザ操作(Claude Browser等)でSNS管理画面を開いて下書きを保存するところまでは問題ないが、
  「公開」「投稿」ボタンを押す前に必ず内容を提示し、ユーザーの同意を得る。
- 短編動画の実際のレンダリング・音声合成・BGM選定などは、著作権のある素材(既存曲・他者の映像)を
  無断使用しない。オリジナル素材またはロイヤリティフリー素材のみ使用する。

## 収益化の全体像・配布方針(2026-09-06更新、詳細は [business-plan.md](business-plan.md))

- **配布方針: App Storeリリースは費用対効果が薄いため見送り。GitHub公開+Web発信の2本柱に絞る。**
  そのためCTAは「アプリを今すぐ入手」ではなく「フォロー/続報待ち」「GitHubで見る」路線にすること
  (marketing下書きは既にこの方針で書かれている)。
- 収益化はApp Store課金・広告ではなく、GitHub Sponsors等の寄付・note記事の有料化・個人ブランディング
  といった間接的な形を想定(business-plan.md 4節)。
- 将来App Store配布を再検討する可能性はゼロではない。その場合はApple Review Guidelines
  (4.2最低限機能性・5.1.1データ最小化・5.1.2データ共有透明性等)への抵触リスクを事前調査済み
  (business-plan.md 4-補節)。単機能アプリのままでは却下リスクが高いことを前提に判断すること。
- 収益化の意思決定(価格・課金モデル)はユーザーが行う。Claudeは選択肢の整理・トレードオフの提示までを担う。
- **GitHubで実際に公開する前は必ず**、Botトークン・chat_id・個人名等の秘密/個人情報が過去のコミット
  履歴に残っていないか再監査すること(../CLAUDE.md参照。2026-09-06にchat_idの平文残存が1件見つかり
  修正済み)。
